# PS256-only migration

Owner requires PS256 only with no ES384 compatibility. Inbound verification,
return signing, key import, JWKS validation and key generation now use PS256
with RSA-3072 and exponent 65537. Old EC public configuration was removed from
wrangler.jsonc; configure a new PS256 kid, public JWKS and private secret before
deployment. No external configuration or secrets were changed.

Active protocol and receiver documentation, fixtures and test signatures were
updated. Historical evidence remains unchanged. The earlier dual-algorithm
implementation was superseded before deployment.

Validation via `mise exec pnpm@12.0.0 -- pnpm run <script>`:

- `format`: passed.
- `lint:check`: passed without warnings.
- `typecheck`: passed.
- `test`: 21 files, 2154 tests passed in 48.12 seconds. Includes genuine ES384
  token rejection before JWKS lookup, EC public/private key rejection, PS256
  inbound and return verification, wrong-key and undersized RSA rejection.
- `keys:generate -- /tmp/jump-ps256-check-20261112-0043 ps256-validation`:
  passed, PS256, modulus_bits=3072, pair_check_ok=true. Generated only isolated
  temporary validation material; no production key was generated or changed.
- `git diff --check`: passed.

these were updated to exercise the RSA contract before the final passing run.
