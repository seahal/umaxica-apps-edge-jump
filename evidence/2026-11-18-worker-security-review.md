# Jump Worker のセキュリティ調査

対象は 2026-11-18 の `39deaf1672ed7f5a58caa2b21d2fbf00a56cb9f9`。Cloudflare の入口から応答、外部通信、鍵バインディングまで追跡し、既存テストと本番構成のローカルビルドを確認した。稼働中のサービス、アカウント、受信側 Rails の現行実装は調査対象に含めていない。

## 確認した問題

- **開発依存の ReDoS（アドバイザリ High）**。`pnpm audit --json` は `picomatch@4.0.7` を1件報告した。影響には glob パターンと照合文字列が関係する。33本の依存経路は Knip、Vitest、Vite Plus、coverage に限られる。Knip のインストール済み `dist/util/glob-core.js` はパターンを picomatch に渡す。PR の CI はチェックアウトされた設定・ファイルを入力に Knip とテストを実行するため、PR の変更はこの処理に届きうる。実行時間上限は該当ジョブごとに15分。現在の設定での停止・遅延は実測していない。本番の Wrangler ビルド入力134件に picomatch は0件で、公開リクエストからの経路はない。照会時点で修正版の掲載なし。[ロックファイル](../pnpm-lock.yaml#L1924)・[CI](../.github/workflows/integration.yaml#L18)・[GHSA-fc5q-39xc-vjpf](https://github.com/advisories/GHSA-fc5q-39xc-vjpf)
- **署名鍵を含む生成物の誤コミット余地**。鍵生成 CLI は指定ディレクトリに秘密鍵を二重に書く。`private.pem` と `wrangler-secrets.json` はともにモード 0600 だが、通常のリポジトリ内パスで `git check-ignore --no-index` が除外したのは PEM のみ。追跡中の同名 JSON は0件。運用手順どおりリポジトリ外で生成すればこの経路は生じない。生成ファイル名を Git の除外対象に加えると誤登録を防げる。[生成処理](../scripts/generate-jump-keypair.mjs#L71)・[除外規則](../.gitignore#L182)・[鍵ローテーション手順](../docs/operations/key-rotation.md#L95)
- **公開 JWKS から設定中の拡張属性が露出しうる**。標準の秘密鍵成分は拒否するが、検証関数が各 JWK の入力オブジェクト全体を返し、匿名の鍵配布 API が JSON 化する。前提は運用側が有効な公開鍵に余分な属性を混入させること。追跡中の本番用 JWKS は `kty,n,e,kid,alg,use` のみで、実際の漏えいは確認していない。公開用オブジェクトを必要な公開属性から組み立てることで境界を閉じられる。[JWK 検証](../src/core/jump_jwks.ts#L34)・[鍵の読み込み](../src/cloudflare.ts#L360)・[配布 API](../src/index.ts#L181)

## 認証・認可と公開経路

- サインアップ、ログイン、メール確認、パスワードリセット、招待、OTP/SMS、セッション、API キー、ユーザー・権限テーブルの実装はない。CAPTCHA の強制、確認前の利用、削除・無効化・パスワードや権限の変更後のアカウント失効、リセット・招待の乱数・期限・一回消費は発行元・受信側で要確認。Jump における直接の HTTP 呼び出しは可能。Fetch Metadata のないクライアントにもサーバーで同じ署名・宛先検証がかかる。[入口](../src/index.ts#L95)・[Fetch Metadata](../src/core/fetch_metadata.ts#L33)
- 匿名の GET/HEAD は `/`（クエリなしは `/about` へ）、`/about`、`/health`、`/health.json`、`/health.html`、`/favicon.ico`、`/robots.txt`、`/sitemap.xml`、`/.well-known/jwks.json`。トークン付きルートは GET のみで、正当な署名付き指示の成功時に 302 を返す。health の JSON は状態・サービス名・公開バージョン・実行基盤・時刻。RPC、Server Action、GraphQL、WebSocket、管理 API、ユーザー別 Storage API は見当たらない。ASSETS が扱うのは favicon のみ。[ルート](../src/index.ts#L162)・[アセット](../src/cloudflare.ts#L276)
- 認可単位は発行元と許可された宛先 origin の組。検証前の `iss` は固定レジストリの検索にだけ使う。署名検証後に発行元別の辺を照合し、同一 origin への遷移を拒否する。URL・query は検証後の Location に届き、body、ユーザー ID、tenant ID 等から DB・オブジェクトの読み書きや role 判定に至る経路はない。許可 origin 内の個々のパスへのアクセス権は受信側が判断する。パス固有の拒否リストは空。[処理順](../src/core/handle_jump.ts#L52)・[辺の検証](../src/core/policy.ts#L5)・[パス規則](../src/core/redirect_policy.ts#L58)
- JWT は PS256 と RSA-3072 の登録鍵、厳密な issuer、文字列 audience、sub、許可されたヘッダー・claim、整数の iat/nbf/exp を検証。入力 TTL 最大30秒、時計差5秒。失効指定 kid はキャッシュ参照より先に拒否する。本番の typ は往復とも JWT、staging は方向別の専用 typ。環境の origin と typ の不一致を拒否するが、入力発行元のレジストリは共通。デプロイ済み鍵の独立性は未確認。OAuth の redirect_uri は構文と転送条件を検証し、一部の native loopback や独自スキームも通す。client_id に登録された URI との完全一致、state・nonce・PKCE は認可サーバー・クライアントの責務。[JWT](../src/core/verify_jwt.ts#L76)・[claim](../src/core/verify_jwt.ts#L147)・[環境](../src/core/token_profile.ts#L10)・[URI](../src/core/redirect_policy.ts#L108)
- **URL 露出と再利用**。`rt` は URL 上の署名付き JWS で、遷移先の query も読める。ログアウト等による利用者単位の失効や一回消費は行わず、同じ有効な入力から別の UUID と新たな30秒の期限を持つ戻りトークンを発行する。既存テストでも別々の jti を確認。履歴、共有 URL、受信側ログにトークンが残ると、内容の露出と期限内の再利用が起こりうる。受信側でのログイン成立・操作実行や実際の漏えいは未確認。[発行](../src/core/handle_jump.ts#L98)・[テスト](../test/strict-hardening.test.ts#L833)・[受容済みの再利用リスク](../adr/0010-accept-stateless-token-reuse.md)・[受信側契約](../docs/receiver-contract.md)

## 注入・濫用・露出

- HTML は JSX、XML はエスケープ済みの設定 origin、未加工の script/style 挿入は定数。Location は許可した HTTPS origin、直接パス、予約 query・制御文字の検証後に作る。サーバーは遷移先を fetch しない。外部 HTTP は登録 issuer の固定 HTTPS JWKS のみで 3xx を追わない。localhost、プライベートネットワーク、metadata endpoint を利用者が fetch 先に指定する経路は見当たらない。SQL、NoSQL、検索、Markdown、メール、CSV、アップロード、要求由来のファイル操作・コマンド実行・動的コード評価・DOM HTML 挿入の sink も見当たらない。JWT/JWKS の JSON.parse 後には形・型の検証がある。[HTML](../src/core/page.tsx#L145)・[URL](../src/core/normalize_url.ts#L332)・[外部通信](../src/core/fetch_jwks.ts#L14)
- **資源と上限**。匿名リクエストは Worker 実行・応答・ログを消費し、登録 issuer の鍵取得と署名検証は認証完了前にも動く。ルートの署名は指示の検証後、公開 JWKS もキャッシュ初期化時に鍵ペアを確認する。JWKS は64 KiB・最大4鍵、isolate ごとの取得共有、30秒キャッシュ、強制更新10秒間隔、処理期限1秒。Cloudflare の制限は IP・拠点単位で600回/60秒、全体の厳密な上限ではない。メソッド・不正 query の早期拒否はカウンタより前。正常な binding の呼出例外時は記録して処理を続行し、上限超過は429、binding・IP 不備は拒否する。追加 WAF やアカウント全体の枠は未確認。メール・SMS・LLM・決済・重いメディア/GIS・DB・queue の呼び出しは見当たらない。[制限](../src/cloudflare.ts#L166)・[例外時](../src/cloudflare.ts#L230)・[キャッシュ](../src/core/jwks_cache.ts#L39)・[ADR 0009](../adr/0009-accept-rate-limiter-fail-open.md)・[Cloudflare の仕様](https://developers.cloudflare.com/workers/runtime-apis/bindings/rate-limit/)
- JWT・要件不一致の多くは同じ言語なら共通の 400 ページとエラー分類。成功の302、過負荷の429、インフラ障害の5xxは区別可能で、鍵取得・暗号処理の有無で応答時間も異なりうる。ユーザー・招待・API キー・決済情報を検索する処理はなく、これらの列挙に結びつく分岐は確認できなかった。応答時間・サイズの実環境測定は行っていない。[エラー分類](../src/core/public_error.ts#L46)
- 本番経路は HTTPS のカスタムドメイン、workers.dev は無効、staging の routes は空。開発スクリプトは全インターフェースの5209番で待受する。開発機で起動した場合の到達性は FW に依存し、E2E サーバーは loopback の4173番が既定。アセット元は public のみ。生成された JS と source map は Worker ビルド出力で、公開アセットに含まれない。.git、.env、debug/metrics、管理 UI、DB、Redis、SSH を配信・公開する設定は見当たらない。[デプロイ設定](../wrangler.jsonc#L4)・[開発スクリプト](../package.json#L11)・[E2E](../e2e/server.ts#L6)
- HTTPS origin 照合、HSTS 1年・includeSubDomains・preload 指定、CSP default-src none と定数ハッシュ、no-store、no-referrer、Set-Cookie 除去、CORS 許可の付与なし。アプリログは要求パスを限定し、構造化ログは許可属性に絞る。Cloudflare 設定はリクエスト URL の query をマスクするが、プラットフォームのパスと受信側のログは別。TLS の実際の設定、ログ保管内容は未確認。追跡テキスト内の限定的な PEM・トークン形式検索に該当なし。Git 全履歴・稼働時 secret の検査ではない。[ヘッダー](../src/core/security_headers.ts#L63)・[ログ](../src/index.ts#L254)・[プラットフォーム設定](../wrangler.jsonc#L43)
