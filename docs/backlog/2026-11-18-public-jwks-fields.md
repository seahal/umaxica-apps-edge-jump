# 公開 JWKS に含める鍵属性の限定

2026-11-18 時点で対応判断待ち。

## 調査結果

`GET /.well-known/jwks.json` は認証なしで取得できる。設定から鍵を読み込む際、
標準の秘密鍵成分は拒否するが、検証を通った各 JWK は元のオブジェクトごと配信する。
運用者が有効な公開鍵に内部用の属性を加えると、その値も公開される。
追跡中の本番用 JWKS に含まれていたのは `kty`、`n`、`e`、`kid`、`alg`、`use` の6属性で、実際の漏えいは確認していない。[JWK の検証](../../src/core/jump_jwks.ts#L34)・[配布ルート](../../src/index.ts#L181)・[調査記録](../../evidence/2026-11-18-worker-security-review.md)

## 後日判断すること

配布する JWK を受信側が使う公開属性から組み立てるか判断する。
現行の6属性に加え、設定可能な `key_ops` の扱いも受信側との互換性を踏まえて決める。
採用した場合は、検証用の公開鍵に無害な識別ラベルを加え、配布応答からそのラベルが除かれること、
配布鍵で署名を検証できること、秘密鍵成分を含む設定は引き続き拒否されることを確認する。
